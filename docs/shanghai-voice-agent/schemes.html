推荐落地路径

第 1 周 · POC（方案一）

Qwen3.5-Omni-Plus-Realtime + instructions「全程上海话」→ 验证延迟、打断、听感。

第 2–3 周 · 生产（方案二）

fun-asr-realtime + DeepSeek + cosyvoice-v3-flash-realtime；后端新增 WebSocket VoiceGateway。

若 TTS 不够地道

保留 ASR/LLM，TTS 换星辰 TeleTTS-Stream-MultiDialect（方案三）。

技术参数（通用）

部署华东（上海）机房 · 与 API 同区域
TTS 首包目标< 300ms（流式按句切块）

方案一 · Qwen Omni 端到端

单 WebSocket 完成听→想→说，延迟最低，适合快速验证。

推荐 POC
300–800 ms
★★☆☆☆
★★★☆☆
原生 FC / 搜索
  • 模型qwen3.5-omni-plus-realtime 或 Flash 降本版
  • 协议wss://dashscope.aliyuncs.com/api-ws/v1/realtime
  • ASR内置 · 113 种语种/方言识别
  • TTS内置流式输出 · instructions 约束上海话
  • VADsemantic_vad 过滤「嗯」「好的」误触发

优点：无三段拼接、原生打断、接入最快。
缺点：上海话腔调不如专用方言 TTS；Agent 业务逻辑在 Omni 内，与 BlockHub 模块 API 需额外对接。

方案二 · 阿里三段式流水线

ASR + DeepSeek + CosyVoice 流式串联，与现有 BlockHub 后端最契合。

推荐生产
600–1500 ms
★★★★★
★★★★★
★★★★☆
  • ASRfun-asr-realtime · Paraformer 含吴语/上海话 · WebSocket 流式
  • LLM现有 deepseek_client.py · 上海话 system prompt + 模块工具
  • TTScosyvoice-v3-flash-realtime · instruction: 「请用上海话表达。」
  • 网关FastAPI /api/v1/voice/shanghai-agent WebSocket 代理
  • 优化ASR partial 即触发 LLM · LLM 流式按句送 TTS · barge-in 取消播放

优点：完全自控 Agent、可拨通模块 API、发布流程可语音触发。
缺点：需实现状态机与三段流式编排，工程量比方案一大。
