1. 五层解耦模型

flowchart TB L5[L5 产品面
Home/广场/预约/上海话/Admin] L4[L4 入口壳与皮肤
industry_site / workbench / microsite] L3[L3 Composer 编排
改页草稿审批 / 选模块] L2[L2 契约引擎
registry resolver schema manifest] L1[L1 能力包 + 真 API
web-capability-* / capability_* / PG] L5 --> L4 --> L3 --> L2 --> L1
层可独立演进的标志允许依赖
L1 能力只改一包不影响其它能力web-core / flutter-core / 自身 API
L2 契约纯函数：keys→schema/manifest无产品文案、无 LLM
L3 Composer可对任意 app 的 schema 操作L2 API；不直连广场
L4 入口壳换 entry_source 只换壳L2 meta；不改能力实现
L5 产品面可闭源；可换品牌调用发布 API；不反向污染 registry

3. 解耦任务清单（可执行）

P0 · 守住已切开的边

  • CI 保留 personal-draft / schema-approval smoke
  • 独立站回归：无顶栏场景墙；封面显示 industry_name
  • 新增能力必须走路径 A checklist（含 Gtgt）

P1 · 单源与包化

  • micrositeRuntimeSkin：home/runtime 抽 shared 或 codegen 拷贝
  • capability_registry + schema/manifest → 可安装 contract 包
  • Composer 以 npm 工作区包发布，产品页不绑死 UI

P2 · 产品面剥离

  • plaza / booking / shanghai_voice / 邮件投递 标为 product plugins
  • 开源示例仅 chat + approval + 假租户文件后端
  • 白标：android_app_id / npm scope / 文案去 BlockHub
