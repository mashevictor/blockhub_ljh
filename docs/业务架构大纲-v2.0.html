二、契约驱动 · Web/Flutter 解耦

核心原则：后端只产出两份契约——page_schema（UI 树）与 build_manifest（包清单），二者都由同一份能力注册表派生。 Web（runtime-web）与 Flutter（runtime-app）各自实现 Widget 注册表，按 capability_key 渲染，互不依赖对方代码。

① 单一能力源（后端）

  • capability_registry.py → ALL_CAPABILITIES
  • 每条含：widget · web_pkg · flutter_pkg · route · agent_id
  • 43 Capability 入库即注册，是全部 UI 的唯一真相源

② 契约生成（后端）

  • schema_generator.py：keys → page_schema JSON
  • build_manifest.py：keys → web_pkg[] + flutter_pkg[]
  • GET /runtime/{id}/schema|manifest 两端共用

③ Web 端（runtime-web）

  • packages/web-core WidgetHost 按 key 渲染
  • 5 包：chat · approval · dashboard · kb · voice
  • manifest 动态 lazy import 裁剪

④ Flutter 端（runtime-app）

  • 自建 WidgetRegistry，按同一 capability_key 映射
  • Dio+SSE 拉同一 schema/manifest
  • login · chat · approval · report · voice 已落地

10 分钟 Demo 主路径（W3 里程碑 · 当前 ~90%）

  1. 管理员登录 Home/Admin
  2. 描述需求或按行业勾选「智能问答 + 请假审批」
  3. 研判 → 发布 → 获得 webUrl + App 深链
  4. 员工 Web：runtime 问答（PDF citation）+ 提交请假
  5. 主管：待办 Inbox 通过 → 通知触发
  6. 可选：@公开 发布到广场 · 点赞评论
  7. 同 appId Flutter APK 复现主路径
