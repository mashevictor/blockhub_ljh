1. 交付模型（不变式）

一切可交付功能 = Capability。热路径无 LLM。

capability_keys + web_template_id + app_ui_id + entry_source
        │
        ▼
  resolver → page_schema + build_manifest
        │
        ├── runtime-web（web_pkgs 懒加载）
        └── Flutter APK（flutter_pkgs 裁剪）
        │
业务写入 ──▶ PostgreSQL 真 API（空库=空列表；禁止假 seed）
层级职责不做什么
Capability双端包 + 真 API + >> 填表不决定营销站 HTML
ShellTabs / 侧栏 / 落地壳不塞业务假数据
Entry skin独立站色板 / 封面布局不复刻 20 套完整营销站 DOM
Composer对话改页 / 选模块 / 数据流不绕过审批写他人正式版

2. 主数据流转

flowchart LR H[Home 向导/弹幕/模块] --> P[POST /creation/publish] P --> DB[(apps + page_schema + manifest)] DB --> RW[runtime-web /r/id] DB --> APK[Flutter 裁剪构建] RW --> API[/api/v1 业务能力/] API --> PG[(PostgreSQL)] C[CapShipComposer] --> CH[schema/changes 草稿] CH --> AD[管理员 approve] AD --> DB CH -.->|作者 GET schema| RW
个人草稿单侧生效：作者带 Bearer 的 GET schema/manifest 可读 personal_draft； 同事/匿名读正式 apps.page_schema。业务 API 始终真库，不按草稿分叉业务表。
