双轨编排 · 先定状态切换，再定 UI

硬规则：仅「可编排态」（就绪 idle / 已停止 stopped）才能改模块与测试 IN/OUT。 执行中 / 已暂停锁定编辑；用户必须先「停止」才能回来改。已完成 / 失败需「重置」回就绪后再改。

状态机定稿（建议）

把现有 6 态收成两条能力轨：可编排 vs 运行锁定。

可编排态 → 可改 / 可测接口 / 可 >> 命令

  • 就绪 idle：默认态，从未跑或已重置
  • 已停止 stopped：运行中点了「停止」回来

运行锁定 → 不可改模块、禁用测试

  • 执行中 running：只能暂停 / 停止
  • 已暂停 paused：只能继续 / 停止
  • 已完成 / 失败：只读查看；点「重置」→ 就绪 才能改
idle ──▶试运营──▶ running ⇄ paused
  ▲                  │
  │                  ▼ 停止
  │               stopped ──▶再试运营──▶ running
  │                  │
  └────重置──────────┘

running ──自然跑完──▶ completed ──重置──▶ idle
running / paused ──异常──▶ error ──重置──▶ idle

规则：canEdit = phase ∈ { idle, stopped }
     canTestApi = canEdit
     canBizCommand(插入/调用/分析) = canEdit
     拖序 / 删模块 / 编辑说明 = canEdit
