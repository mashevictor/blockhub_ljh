① 用户身份与角色（User.role）

后端无独立 is_admin 列，权限完全依赖 users.role 字符串 + tenant_id 隔离。

角色 中文 如何产生 JWT 携带 说明
admin 平台 / 演示租户管理员 种子账号 admin@trackchat.local role + tenant_id 跨租户特权；套餐配额豁免；可 seed
tenant_owner 空间所有者 OTP / 企微首次登录即注册自动建个人租户 role + tenant_id 本租户管理员；Admin 侧栏与 admin 同权（除平台 seed）
employee 使用者 / 员工 种子 employee@…；模型默认值 role + tenant_id 工作台问答/知识库/审批列表；不可进创建应用等 Admin 菜单
未登录 / 访客 匿名 — 无 JWT Home 广场可读；Runtime config API 实际可匿名；广场发布 API 当前无鉴权（问题）
易混：应用上的 audience = b/c/both 是应用受众，不是用户角色。 Runtime 顶栏出现的「使用者 / employee」来自登录用户的 role 展示。

后端守卫

  • get_current_user — 任意有效 JWT（缺 token → 403）
  • require_admin — admin + tenant_owner
  • require_platform_admin — 仅 admin
  • require_billing_payer — admin + tenant_owner

前端守卫

  • Admin：ProtectedRoute（有 token）+ RoleGate
  • canAccessRole：allowed 含 admin 时，tenant_owner 一并放行
  • Home：计费页手动跳 Admin 登录
  • Runtime：独立 token，页内强制登录壳
