1. Registry 是什么？（别被英文吓到）

Registry = 能力黄页 / 能力目录表。 本仓里主要指 backend/app/data/capability_registry.py： 登记「有哪些业务能力可被选型」，每个条目有稳定的 key（如 device_repair、approval_flow）。

生活类比

  • 超市货架目录 = registry
  • 货架上的商品 = 能力包（Web Widget + Flutter 包）
  • 你勾选放进购物车 = capability_keys
  • 收银出单 = publish → page_schema + build_manifest
≈

工程对应

  • 目录表：capability_registry.py
  • 商品：web-capability-* + capability_*
  • 购物车：发布时传入的 keys
  • 出单：菜单/路由/要装哪些包

Registry 不是：业务数据库、审批流引擎、也不是「对话改页」本身。 它只回答：「这个 key 存在吗？对应哪个双端包？菜单怎么挂？」

3. 两类「能力」——最容易混的地方

中文都叫「能力」，工程上要拆开，否则就会问「对话改页要不要进 registry？」

A. 业务 Capability（进 Registry）

  • 例子：报修 device_repair、审批 approval_flow
  • 用户勾选后进菜单
  • 必须有双端包 + 真 API + 真表
  • 空库 = 空列表（选型即交付）
  • 路径：写 registry → Alembic → API → web/app 包

B. 平台编排（不进 Registry）

  • 例子：对话改页、草稿审批、选模块 Dock
  • 用户不勾选也能用（Runtime 自带）
  • 改的是 page_schema，不是业务单据
  • 包名：@capship/composer，不是 web-capability-*
  • 文档：capship.html §12 / schema-approval skill

为什么对话改页不进 registry？ 因为它不是「可选业务模块」，而是改整个应用页面契约的壳级工具。 若硬注册成 schema_change 假 key，会破坏「选型即交付」语义（勾了却没有业务表）。

4. CapShip 开源与本仓如何解耦

本 monorepo（积木仓 / BlockHub）= CapShip 开源核 + 产品面超集。 开源抽出后，产品仓通过包依赖 CapShip，而不是复制两份 registry。

开源核要带走什么

  • Registry 契约与解析
  • page_schema / build_manifest
  • 双端 Runtime 壳
  • Composer + 改页审批参考实现
  • 示范能力包（如 chat + approval）

产品面通常留下什么

  • B2B 官网文案与 Hero
  • 广场、预约演示线索
  • 行业深度包营销内容
  • 上海话等运营特色场景包装

细节边界表见 capship-scope-boundary.html。

6. 对话改页落在哪？（相对 Registry 的旁路）

发布之后，用户在 Runtime 里用 Composer「对话改页」。 这是改契约的路径，不经过「再勾选一个 registry key」。

sequenceDiagram autonumber actor U as 用户 participant Dock as Composer Dock participant LLM as compose-edit API participant DB as schema_change_requests actor Admin as 管理员 participant App as apps.page_schema U->>Dock: 对话改页 Dock->>LLM: 生成 ops Dock->>Dock: 左侧即时预览（正式 schema 未变） U->>DB: 保存草稿 draft U->>DB: 提交审批 pending Admin->>DB: approve DB->>App: 写入正式 page_schema + rev++ Note over App: 全员 Runtime 读正式版 
业务能力路径：  勾选 key → Registry → 菜单挂业务包
平台改页路径：  对话改页 → 草稿/审批 → 写回 page_schema
二者正交：改页可以增删菜单项，但仍应指向已注册的真能力 key

7. 一分钟 FAQ

问题 短答
Registry 是数据库表吗？ 主要是代码里的目录（可再同步到 catalog）；业务数据在各能力自己的表里。
开源 = 整个本仓吗？ 否。开源是 L2–L4 + Composer；官网/广场等是产品面。
对话改页是开源能力吗？ 是，但是平台编排能力，不是 registry 里的业务模块。
为什么首页也要写对话改页？ 产品叙事对齐 Runtime；避免用户以为只有「勾选模块」一种创建方式。
新业务功能怎么加？ 走路径 A：registry key → 表/API → 双端包。见 capship.html §6。
记住这句话： Registry 管「有哪些积木可勾选」； Composer 管「对话怎么改房子平面图」； Runtime 管「房子怎么住人」； 产品面管「怎么把房子卖出去」。
