CapShip · 开源范围与能力边界

Capability → Ship：选型即交付引擎。本文划定「开源 CapShip 做什么 / 不做什么」， 以及与积木仓 BlockHub 产品仓的数据流转分界。许可建议 Apache-2.0；契约 SSOT 仍以 capship.html 为准。

1. 一句话定义

CapShip = 把「选中的能力 + 壳模板」编译成可运行的 page_schema + build_manifest，并在 Web / App 运行时按清单裁剪加载。

它解决「如何建成可交付产品」；不解决「智能体如何思考」「如何做向量检索」「如何运营广场」。

2. 范围：In Scope / Out of Scope

✓ 开源必须包含

  • Capability Registry（能力定义与推导）
  • Resolver：keys → 合法集合 + dropped_keys
  • Schema / Manifest 生成器
  • Web / App 壳模板枚举（tabs / sidebar / landing × bottom_tabs / drawer / immersive）
  • web-core + 最小 web-runtime（WidgetHost）
  • flutter-core + 最小 runtime 壳 + manifest 裁剪脚本
  • 示范能力包：如 chat_qa、approval_flow（含真 API 参考实现）
  • Composer 契约（对话改页 / 选模块）— 可与 runtime 同仓或 peer
  • 路径 B：codegen 预览接口（可选插件，文案禁止夸大）

✗ 开源明确不包含

  • 积木仓 Home 官网 / 广场 / 预约演示
  • 上海话语音、电信星级方案等产品插件
  • 20 行业独立站营销 HTML 与行业 Catalog 全文
  • B2B 商务运营、邮件投递网关、租户计费
  • 完整 Admin 后台与多租户商业策略
  • 把 LangGraph / RAG 做成 CapShip 内核
  • 「一键生成完整 Flutter 工程」级承诺（除非实现水位达标）
  • 像素级复刻 20 套 microsite 营销站

7. 参考 API 最小集合

方法路径开源是否必须
POST/v1/publish必须（可文件后端）
GET/v1/apps/{id}/schema必须（含 personal_draft 语义）
GET/v1/apps/{id}/manifest必须
POST/v1/apps/{id}/schema/changes建议
POST/.../changes/{id}/approve建议
GET/v1/apps/{id}/download可选（APK worker）
*plaza / booking / voice禁止进入开源核

8. 贡献红线（开源治理）

  • 新增能力必须路径 A：registry + 双端包 + 真存储说明；禁止只交预览页冒充完成
  • Runtime 业务写入必须 >> 单字段步进（Gtgt），禁止多框同屏作为主路径
  • 不得把产品品牌硬编码进 contract 默认推荐
  • 路径 B 文案只能写「预览/生成中」，禁止「已生成完整 App 工程」
  • PR 若引入产品面模块到 packages/contract 或 web-runtime 核心 → 驳回

与积木仓的一句话关系

BlockHub = CapShip 核心 + 产品面。 开源只保证「能力如何被建成产品」；行业独立站、广场增长、语音特色继续由产品仓交付。
