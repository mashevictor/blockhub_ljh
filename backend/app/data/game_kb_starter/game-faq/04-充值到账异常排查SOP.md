> **合规提示**：本文为游戏运营 / 客服与内容合规知识库**示范文档**，仅供培训与系统检索演示。不替代官方公告、法务签发的版号材料或平台审核政策原文。

# 充值到账异常排查 SOP（示范）

## 一、适用场景

- 玩家反馈已扣款但游戏内未收到对应货币/道具。
- 渠道回调状态异常（如超时、重复通知、签名错误）。
- 订单状态在游戏后台显示“支付成功”但未发货。
- 玩家申请补发或退款前的内部核查。

## 二、操作要点

### 2.1 订单信息核对

- **获取订单号**：要求玩家提供渠道订单号（如支付宝交易号、苹果收据、Google Play 订单 ID）及游戏内角色 ID。
- **查询游戏后台**：在订单管理模块搜索订单号，核对以下字段：
  - 订单状态（待支付/支付成功/发货成功/发货失败）
  - 商品 ID、金额、购买时间
  - 角色 ID 与区服
- **渠道对账**：登录渠道商户平台，查询该订单的支付状态、回调记录。

### 2.2 异常分类处理

| 异常类型 | 处理方式 |
|----------|----------|
| 渠道显示支付成功，游戏未收到回调 | 手动触发补单接口（或联系技术重推回调） |
| 回调已收到但发货失败（如库存不足） | 检查商品配置，手动补发并记录 |
| 重复回调导致多次发货 | 冻结多余道具，联系玩家协商回收或补偿 |
| 订单号不存在或信息不匹配 | 要求玩家提供更多凭证（如支付截图、银行流水） |

### 2.3 补发条件

- **必须满足**：
  - 渠道侧确认扣款成功。
  - 游戏内订单状态为“支付成功”但“发货失败”或“未发货”。
  - 同一订单未补发过。
- **禁止补发**：
  - 玩家无法提供有效订单号或支付凭证。
  - 渠道侧显示退款或撤销。
  - 超过 30 天未反馈（视运营策略调整）。

### 2.4 工单关闭标准

- 补发成功且玩家确认到账。
- 玩家同意等待技术修复（需设置回访时间）。
- 经核实为玩家误报（如记错角色、已到账未刷新），需附截图说明。
- 渠道退款处理完成，游戏内已扣除对应道具。

## 三、记录字段

工单或后台日志应包含以下字段：

| 字段 | 示例 | 说明 |
|------|------|------|
| 工单 ID | CS20250321001 | 唯一标识 |
| 玩家角色 ID | 12345678 | 游戏内唯一 ID |
| 渠道订单号 | 202503212200141234 | 渠道侧订单号 |
| 游戏订单号 | GAME20250321001 | 游戏侧订单号 |
| 商品 ID | gold_648 | 商品配置 ID |
| 金额 | 648.00 | 单位：元 |
| 渠道 | App Store | 支付渠道名称 |
| 异常类型 | 回调超时 | 按分类填写 |
| 处理结果 | 已补发 | 补发/退款/待处理等 |
| 处理人 | 客服张三 | 操作人员 |
| 处理时间 | 2025-03-21 14:30:00 | 精确到秒 |

## 四、与信息系统联动

- **游戏后台对接**：客服系统通过 API 查询订单状态、触发补单、记录补发日志。
- **渠道对账系统**：每日自动拉取渠道结算单，与游戏订单比对，标记异常订单。
- **自动化补发**：对于明确回调成功但发货失败的订单，系统可自动重试 3 次，仍失败则生成工单。
- **风控联动**：同一角色频繁补发触发风控审核，需主管审批。

## 五、常见误区

1. **仅凭玩家截图补发**：截图可能伪造，必须以渠道商户平台或游戏后台数据为准。
2. **忽略渠道回调延迟**：部分渠道回调可能延迟 5-10 分钟，建议等待 15 分钟后再处理。
3. **重复补发**：未检查历史补发记录，导致同一订单多次补发，造成资产溢出。
4. **未记录处理详情**：补发后未在工单中记录补发时间、道具、操作人，后续审计困难。
5. **混淆渠道订单号与游戏订单号**：导致查询错误，延误处理。

## 六、示范摘要

> 依据《关于规范网络游戏运营加强事中事后监管工作的通知》中关于“用户充值必须及时到账”的原则，运营方应建立充值异常处理机制。本 SOP 旨在规范操作流程，确保玩家权益与游戏经济平衡。
